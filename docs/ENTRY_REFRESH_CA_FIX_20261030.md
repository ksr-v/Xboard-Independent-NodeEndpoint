# 沿用证书的入口刷新修复

本次补充发布为 **root-installer-v1.0.12 / tools 1.0.13 / web-manager 1.0.2**，替代上一版入口修复的升级命令。保留旧标签和资产原字节。

## 已确认的问题

上一版的同地址入口刷新仍调用 `existing_password()` 获取面板托管的 CA 口令，但未使用返回值。即使现有证书通过严格校验、原入口 TLS/API 正常，只要面板口令读取子进程失败，路由刷新也会提前中止并恢复旧配置。这次失败发生在 Nginx 配置写入前。

新版在地址不变、沿用现有证书时只读检查 Root 托管元数据、应用绑定和公开 CA 指纹，不取口令、不恢复待完成的凭据操作、不写口令元数据。新建 CA、变更证书地址、续签、轮换和需要证明旧身份的 Docker 换绑，继续使用原有私钥及口令验证流程。

同时补齐事务诊断：回滚后的提示包含失败阶段，备份目录下的 `FAILURE.json` 以 `0600` 保存受限的异常类型链、数值错误码及回滚状态，不保存异常消息、命令参数或命令输出。诊断写入失败不会阻断原有恢复。

## 已有原生面板一键升级

在 Xboard 面板服务器的交互式 Root SSH 中执行：

```bash
nodeendpoint_script=$(curl -fsS --proto '=https' --tlsv1.2 --connect-timeout 15 --max-time 60 --max-filesize 65536 https://raw.githubusercontent.com/ksr-v/Xboard-Independent-NodeEndpoint/root-installer-v1.0.12/install.sh) && [ -n "$nodeendpoint_script" ] && bash -c "$nodeendpoint_script" -- --upgrade-entry
```

核对屏幕显示的原站点、IP、端口，按提示输入完整确认文本。新助手兼容前两版已发布的 Root 策略，在原授权范围内升级，保留批准端口和 enabled/active 状态。原入口、CA、服务器证书及密钥沿用现有文件。未安装助手时仅刷新入口，不新增授权。

上一版已经升级助手但路由随后回滚的站点也使用本命令，无需卸载助手或重建 CA。若元数据不完整、绑定不匹配或有指向当前 CA 的待完成凭据操作，工具仍会停止并显示固定原因。

## 升级后验证

升级成功后，设备准入的两个精确路径在无凭据 GET 检查中应返回 `405`。随后恢复测试账号原有设备限额并重新连接客户端，以真实代理请求确认。入口路由与设备限制的背景见[设备准入入口修复](DEVICE_ADMISSION_ENTRY_FIX_20261030.md)。

本次修复解除的是纯路由刷新对 CA 口令读取的多余依赖；它不伪造或重建面板托管口令。若后续真正需要签名的操作仍无法读取口令，应继续排查其面板凭据服务。

## 验证记录

同版 `VERIFICATION.json` 列出精确发行资产的回归、公开下载及隔离集成范围。受控测试中的面板桥接失败只用于验证本次刷新路径，不代表生产凭据服务已被修复。真实账号及生产入口的最终结果以升级后的现场验证为准。
