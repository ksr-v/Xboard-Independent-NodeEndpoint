# node 管理菜单与配置编辑（2026-10-25）

已实现：在标准 Linux/systemd 节点输入小写 `node`，可修改对接面板地址和 Token、查看最近日志、重启、查看状态，以及在线更新。原有菜单编号1、2、3保持对应更新、重启、卸载。

本轮为本地开发及验证结果，**尚未推送或发布新 Release**。当前公开 Node `v1.13-orphan.5` 和全插件包不包含新增菜单／配置编辑器。第一次需要配套升级包含本功能的 Node、xbctl 和安装脚本；获得新菜单后，后续直接选1更新。后端和插件本轮没有修改，无需重建 NodeEndpoint CA。

## 使用方法

SSH 登录节点后输入：

```bash
node
```

```text
1) 在线更新到最新正式版本（保留绑定）
2) 重启节点
3) 卸载
4) 修改对接面板地址 / Token
5) 查看最近日志
6) 查看状态
0) 退出
```

非 Root 用户沿用 sudo 流程。如果已有 Node.js 的 `node` 命令，安装器会拒绝覆盖／遮蔽，需要先处理冲突。每次执行一项操作后退出，再次输入 `node` 即可进入菜单。

选择4：多个绑定时先选择编号，输入新面板 HTTPS 地址和新 Token；单项留空保留原值，全部留空取消。Token 隐藏输入，经 stdin 写入私有临时文件，不进入外部命令参数。只修改目标绑定，保留 machine/node ID、原实例身份、数据目录、其他绑定和未知配置字段。共用环境变量的绑定更换 Token 时使用独立新引用。

编辑前核对实际 systemd 单元、ExecStart、EnvironmentFile 和环境；自定义 drop-in／启动命令停止自动编辑。先校验 TLS 和实际面板认证，不跟随重定向；成功后备份、停服、替换配置和凭据，恢复原运行状态。重启／健康检查失败尝试回退；原来停止的服务保存后仍停止。更新和重启会中断现有代理连接。

保留本机 NodeEndpoint 公共 CA bundle，证书仍须覆盖新地址；换到另一台面板时，还需有该面板对应的信任及相同 machine/node 身份。配置／凭据0600、备份目录0700。旧凭据行及私有恢复备份不自动删除。YAML 别名、合并键、多文档、重复键和 standalone 配置拒绝自动编辑，避免丢失或误认配置。

选择5显示 `xboard-node.service` 最近100行 journal，不无限跟随。日志可能含运行数据，分享时应脱敏。

## 在线更新来源

固定查询用户维护的 `ksr-v/Xboard-Node--Custom-Source` 最新正式 Release；拒绝草稿、预发布、不符的仓库／tag、重复或未上传资产。完整获取同一 tag 的 `install.sh` 和 `SHA256SUMS`，核对唯一安装器摘要及 API 提供的资产 digest，再检查 Bash 语法和升级接口。清除旧下载来源覆盖变量后执行该版安装器的 `upgrade`；Node／xbctl 仍由安装器固定二进制 SHA-256。

网络失败、部分下载和摘要不符均停止，不回退执行 dev 脚本。保留绑定、配置、CA 和健康端口，配套替换 Node、xbctl 和本地菜单脚本。重复选择同一正式版本也会重装并重启。GitHub API 限流时需稍后再试。

发布维护要求：同一正式 tag 同时提供匹配源码的安装器、安装器摘要清单、amd64／arm64 的 Node 和 xbctl，更新四个二进制 pin。当前 v5 资产布局已只读核对；本轮没有执行公网更新器，也没有创建测试 tag 的公开 Release。
