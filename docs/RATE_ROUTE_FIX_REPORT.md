## 修复内容

- **sing-box 低速卡死与计数后限速偏差**：令牌等待分片并检查失败预留；保留实际 I/O 限速层，在数据转发前按块限速，避免 Linux splice/计数回调已经发送大块数据后才等待。已知用户即使当前无限速，也保留可更新的门控，保证后续启用无需重连。
- **Xray VLESS 上传未限速**：维护固定核心的 `DispatchLink` 上行门控，保留 mux/XUDP 所依赖的原 Reader 类型；上传、下载共享同一用户的桶。UUID 与协议邮箱映射到同一桶。
- **两内核的已有连接限速开关**：所有已知用户保留稳定桶指针，正数与无限速之间只更新桶，不删除/替换已有连接引用。
- **路由与出站一起应用**：新增、修改、删除出站与规则形成完整配置；预验证失败保持现有服务，启动失败显式恢复最后成功配置，保留之后的用户更新及累计流量。移除了 Xray 旧路由最多后台保留五分钟的路径。
- **失败更新不会覆盖回滚**：服务层保留恢复成功的内核，不再用同一失败配置立即覆盖；失败配置不标记为已接受，即使后续 API 返回 304 也能重试。
- **sing-box 入站及认证更新边界**：端口/TLS 等入站变化也使用完整候选和失败回滚；固定依赖的认证表不支持并发原地替换，用户新增、移除及 UUID 变化改为完整候选切换，会关闭本节点旧流。只改变限速或设备数量限制不替换认证表，保持已有连接。用户事件使用已接受的路由快照，不顺带应用编辑中的本地规则文件。
- **Xray 精确域名**：裸域名转为 `full:` 精确匹配；已有显式匹配前缀保持兼容。
- **后端**：隐藏但启用的节点也收到提交后的路由更新；用户限速拒绝负数；路由按 `route_ids` 的选择顺序下发，忽略已删除 ID、合并重复 ID。套餐“强制更新”绕过模型观察器的批量更新，也在提交后同步旧、新权限组，避免遗漏限速更新或用户移除。

结构化本地规则的多字段 **OR** 语义保持，并补充文档。当前面板管理原生 `custom_routes`，不表示已新增 `custom_route_rules` 的存储或 API。

## 部署范围与实验程序

生产生效需要部署本次 **独立 Xboard 后端和 xboard-node** 修复代码。只重装 NodeEndpoint 插件 ZIP 不会替换节点内核或后端观察器。既有公开版本及其默认安装命令不会自动获得未发布的修复；本轮没有升级生产数据库、执行生产安装器或替换生产服务。

路由更新会让当前节点既有连接重连；sing-box 入站参数或用户身份变化也会关闭该节点旧流。限速更新无需主动断开连接。升级后应核对重叠路由的选择顺序，因为现在明确按该顺序执行首次匹配。不要把 Xray 原生 `settings` 直接用于 sing-box。

`tests/e2e/rate_route_fixed_*` 是本次固定 VM、镜像、日期及路径的实验辅助程序，不是生产部署命令。候选 metadata 示例仅含公开摘要，实际合成凭据和原始运行日志留在 VM Root 私有目录。

**未验证/延期**：完整 UDP/QUIC 吞吐限速、其他代理协议、ARM64 运行、外网链路、长期压力、生产面板及公网客户端连续性。在正式发行/部署阶段补充对应范围验证，不以本次 TCP 或 UDP 关联关闭测试替代。
