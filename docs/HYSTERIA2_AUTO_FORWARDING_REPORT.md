# Hysteria2 自动 UDP 范围转发（2026-10-25）

已实现：新版独立后端向节点下发合法的 Hysteria2 跳跃范围，Node 在启动、配置更新及退出时自动管理该范围到实际 UDP 监听口的转发。**不再需要为本功能手写 NAT 规则；主机防火墙、云安全组和外部路由的 UDP 放行仍由原策略控制。**

本次完成专用 VM 真实联测并本地提交，尚未推送或发布新 Release。当前公开的 Node `v1.13-orphan.5`、后端 `v2026.10.25.1` 安装命令和全插件发行包未自动获得该功能。此前[手工映射实验报告](HYSTERIA2_PORT_HOPPING_TEST_REPORT.md)保留当时版本的结果。

## 面板如何配置

在 Hysteria 节点选版本 **2**，例如连接端口填 `42450-42453`、服务监听端口填 `42443`，跳跃间隔填 `5` 秒。节点收到范围后自动创建转发；更改范围后替换自身规则；连接端口改为单端口后撤销自身转发。正常停服、重启、卸载会清理自身规则，重新启动后按面板最新配置恢复。

需要配套部署包含本功能的**独立 Xboard 后端和 Node**。无需数据库迁移、卸载其他插件或重建 NodeEndpoint CA；只更新插件 ZIP 不足以增加节点的 NAT 管理逻辑。建议先备份和更新后端，再逐台升级 Node。新安装器补装 `nftables`，在停服替换前检查工具可用性；既有服务权限不被自动放宽。

节点需运行在具有 `CAP_NET_ADMIN`、nftables、Linux NAT 支持和可写 `/run` 的环境。Docker 仅能管理其所在网络命名空间，容器权限、宿主端口发布和云安全组不能由容器内 NAT 代替。新功能没有关闭 `NoNewPrivileges` 或改 INPUT 默认策略。

## 配置契约和失败处理

后端新增可选 Node API 字段，GET 与 NodeWorker WS 使用同一生成器：

```json
{"protocol":"hysteria","version":2,"server_port":42443,"port_hopping":{"start":42450,"end":42453}}
```

没有该字段或值为 null 时不启用映射，旧面板仍可对接。旧 Node 会忽略新字段，仍需人工转发或升级。面板只接受 `1..65535` 内的单端口、简单升序范围和单个监听端口；负数间隔、反向范围、超界及混合列表被拒绝。旧表单的 `0` 间隔转为留空默认值，其他协议校验保持原状。畸形旧记录不会被猜测为 Root 规则，需要后台修正。

Node 仅管理带完整 owner 摘要标记的 `inet xbnode_hop_<24位摘要>` 表，使用受控参数与 stdin 调用 nft，不拼接 Shell。规则限定 UDP、本机目标地址和监听地址族；不改全局防火墙允许策略，也不写系统 nftables 保存文件。范围包含实际监听口是合法的。

采用原子 nft batch、全局更新锁和实例生命周期锁，拒绝同一活实例的重复进程、其他节点重叠映射、已有 UDP 服务占用、外部 NAT 冲突、归属标记不符及无法可靠判断的复杂规则。旧 iptables-legacy 的 UDP/未知协议 NAT 混用要求先人工统一后端，不自动覆写。

权限、依赖或冲突检查失败时保持当前内核，不把新配置标为已接受；按正常同步周期重试，WS 在线时也不丢失待重试状态。内核更新失败会尝试恢复旧映射；恢复失败单独报错。无跳跃的旧节点在缺少管理权限时仍能运行，但无法保证清理之前遗留的特权规则。异常断电或 SIGKILL 无法立即清理；同一实例重启后核对并接管自身遗留表。

**范围更新可能关闭该节点已有代理连接，客户端需按新配置重连；Go 主进程和面板控制连接保持。** 服务没有符合权限组的用户时可以等待首批用户，再启动监听和转发。

## 已验证

专用 VM `192.168.128.128`，独立网络命名空间与私有 IPv4 veth，真实 QUIC、TLS 验证、sing-box 客户端和 sing-box/Xray 两种服务端内核；没有修改生产面板。客户端采用项目既有固定离线依赖。成功路径的转发规则全部由候选 Node 创建，测试脚本不代为创建。

| standalone 两内核 | **20/20**：自动建表；5 秒间隔持续 45 秒，同一 TCP 和 UDP 会话字节一致；本地文件监视更新范围、旧范围失效、新范围成功、关闭跳跃、主端口继续可用、重新启用、SIGTERM 清理和反向范围拒绝。 |
| 真实面板 machine/NodeWorker | **22/22**：真实 HTTP 引导、Redis 中的 WS 在线状态、实际保存控制器修改范围和关闭跳跃、同一 Go PID 规则更新、真实订阅同步、新旧范围 TCP/UDP 对照、退出清理。 |

45 秒跳跃用例中，sing-box 实际访问4个目的端口，Xray访问3个；两者均更换10个源 socket，间隔约5秒。随机选择可连续重复目标端口，因此不要求每轮改变目标端口或一定覆盖所有端口。TCP每次32KiB、UDP每次1KiB echo，150ms间隔，返回字节逐一比较；不是满载吞吐测试。

真实面板是新建的 loopback `17006` 容器、SQLite、Redis与NodeWorker，不是模拟 API。通过不记录内容的 Unix 字节中继，将隔离网络内的 loopback 连接接到真实面板。面板运行时四插件来自固定基础镜像（NodeEndpoint 1.0.7、SmartExpiry 1.2.0、QR 审计副本1.2.0、FlowScope2.4.0）；本轮覆盖当前后端源码329文件。该实验验证后端/Node功能，不表示已生成新全插件发行包。
