# Hysteria2 UDP 监听口自动放行

配套版本为独立 Node `v1.13-orphan.8`、NodeEndpoint `1.1.1` 和 Xboard `v2026.10.30.1`。本次修复的是节点主机 INPUT 防火墙仍阻断实际监听口的问题。已有跳跃 NAT 正确，并不代表 INPUT 已允许数据包通过；关闭跳跃后单端口也不能连接时，应先检查实际监听口。

## 自动管理的范围

标准安装器为新装及标准升级的 systemd 服务写入 `Environment=XBOARD_NODE_MANAGED_INPUT=1`。Node 根据实际应用成功的 Hysteria2 配置，为该实例的单个 UDP 监听口维护带所有权标记的 INPUT 放行规则。单端口 Hysteria2 也适用，不要求开启端口跳跃。

例如连接端口为 `17443-19443`、实际监听端口为 `17443`：跳跃范围仍由 Node 的 NAT 规则转发至 `17443`，INPUT 只放行实际的 `17443/udp`，不会将整个范围或 TCP 一并放行。若配置指定监听 IP，规则受相应地址与 IP 版本约束；未指定地址时沿用内核的通配监听语义。放行允许所有来源访问这个监听口，节点管理员应在启用前确认符合本机策略。

支持范围为 Linux 主机的 iptables-nft 和 iptables-legacy，分别处理 IPv4 与 IPv6。存在额外原生 nftables INPUT basechain 或 firewalld 管理时，本次不自动修改这些规则，需按实际防火墙人工放行；不能用另一条 nft `accept` 覆盖其他链的 `drop`。Docker 还需核对容器网络命名空间、权限与宿主端口发布，不将宿主环境结论直接套用于容器。

自动 INPUT 管理使用进程级独占租约，同一网络环境只允许一个启用该能力的 Node 进程；该进程内可以有多个节点实例。多个独立 Node 服务不同时争抢规则，应由管理员手动管理其他服务的 INPUT。

云安全组、上游网络和运营商策略仍需人工允许客户端使用的 UDP 端口范围。自动 INPUT 管理不能修复错误地址、TLS / SNI、认证、未监听端口或上游丢包，也不保证客户端已经导入了跳跃范围。

## 生命周期与恢复

Node 在启动、配置变更及每 `30` 秒的独立检查中核对自己的 NAT 和 INPUT 规则，WebSocket 是否连接不影响该周期。只为已成功应用、内核正在运行且有用户的配置恢复规则；待处理或已拒绝的新配置不会被当作当前成功状态。暂时无法应用时保留旧配置并重试，不要求再到面板重复保存。

UFW 的 iptables 兼容布局及 iptables-persistent / netfilter-persistent 重载可能移除运行时规则。Node 正常运行时会在后续周期恢复，期间存在短暂连接中断窗口，不保证防火墙重载零中断。Node 不修改 `/etc/iptables/rules.v4`、`rules.v6`、UFW / 提供商持久配置，不执行全规则保存，不改变 INPUT 默认策略或外部规则。

配置撤销、内核停用、正常停止和卸载只清理本实例的 owned 规则。其他实例、提供商和管理员的规则保留。SIGKILL 或断电无法立即清理；同一稳定实例重新启动后核对并回收自己的遗留规则。未知所有权、规则冲突或无法识别的防火墙布局会拒绝自动处理，不覆盖外部规则。

## 关闭自动管理

本地配置可以明确关闭：

```yaml
firewall:
  managed_input: false
```

顶层值继承给各实例，实例级本地配置可明确覆盖。该本地关闭选择优先于安装器的启用环境变量。自定义服务或直接运行二进制，没有 `XBOARD_NODE_MANAGED_INPUT=1` 时默认关闭；仅在 YAML 中设置 `true` 不能授予主机防火墙修改权限。

安装器的 `--skip-firewall` 将标准服务环境设置为 `XBOARD_NODE_MANAGED_INPUT=0`，后续标准升级保留已有的 `0`。修改本地配置后按本机服务布局重启并核对结果；关闭后由管理员维护实际 UDP 监听口规则。不要通过清空防火墙或修改提供商持久配置来关闭此功能。

## 升级与最小诊断

已有节点按[升级教程](UPGRADE.zh-CN.md)使用固定 v8 安装器的 `upgrade`，保留身份、Token、CA、配置与数据目录。面板复制的新机器安装命令不能代替升级；只上传 NodeEndpoint 插件也不会更新已运行的 Node。

只读检查版本、实际服务与 UDP 监听：

```bash
/usr/local/bin/xboard-node -v
systemctl is-active xboard-node.service
ss -lun '( sport = :17443 )'
```

将端口和服务名替换为实际值。先确认单监听端口能够连接，再验证客户端导入后的端口范围和持续跳跃。提供问题信息时仅提供版本、端口、监听状态及脱敏错误，不公开订阅 URL、Token、密码、私钥或完整防火墙 / 原始日志。

本版验收结果另见[验证范围](RELEASE_VALIDATION_HY2_INPUT_20261030.md)。本文描述实现合同，不将历史 NAT 或其他版本的测试记录计为 v8 已通过。
