
本次修复针对旧安装教程将 `203.0.113.10` 作为可执行 `--host` 参数，导致示例地址被保存并用于服务器证书的问题。新装和恢复命令省略该参数，由安装器显示公网 IPv4 候选，管理员确认或手工覆盖；已有真实入口保留原地址。已安装的错误地址通过显式 `--repair-address` 修改，不重新创建 CA。

地址修复的 16 项检查使用隔离替身验证调用和失败顺序：先检查独立后端能力及已有 CA 状态，再执行 Root `modify`；Root 失败或确认取消时不保存面板设置。Root 已提交而面板保存失败时可重试，不调用新 CA 安装流程；提交后地址或 CA 信任不符时停止。PHP 命令使用记录中的非 Root 应用用户，私有捕获输出，失败提示不转发应用日志。这些检查不实际启动 Nginx 或签发证书。

独立后端新增 11 项检查覆盖首次候选选择、显式地址校验、原地址保留、示例地址拒绝、非交互首次安装不探测或猜测地址，以及 Root 成功后才依次保存设置、处理防火墙和导入公共 CA。已有入口不会被普通升级隐式改址，已有 WS 模式保持。

CA PHP 集成由原 16 项扩展为 18 项，新增真实非 Root PHP CLI 桥接的准备、幂等重试、取回和绑定，以及错误输入、错误主机、错误 APP_KEY、冲突指纹和禁用插件时的拒绝检查。拒绝路径不改变凭据表；普通设置与应用日志不包含测试口令。测试使用隔离数据库和合成凭据。

## 专用虚拟机实际修复

在授权的 `192.168.128.129` 专用虚拟机中，使用隔离 PHP-FPM / Nginx / SQLite 站点及 TCP 19843，以原固定 tools 1.0.4 真实创建 `203.0.113.10` 入口和该地址绑定的托管 CA，再运行本版引导修复：

- 输入 `CANCEL` 后，入口、证书、托管凭据和面板设置保持。
- 确认后停止测试 PHP-FPM，真实触发换证及 Nginx reload 后的服务探测失败；事务恢复旧证书和计划，面板设置没有提前写入。
- 恢复服务后修复至 `192.168.128.129`，服务器证书 SAN 和 Root 计划、插件设置同步，使用原公共 CA 验证实际 IP HTTPS 成功。
- 原 CA PEM、加密私钥、指纹、凭据 ID、数据库密文及 Root 托管映射逐字保持。
- 再次执行修复成功，没有产生新 CA 或新服务器证书。

测试完成后卸载测试入口、停止自建进程，恢复原测试数据库、公共 CA 和防火墙；私有证据保留在测试机 Root 目录中。

## 验证边界

公网候选检查使用模拟响应，没有向外部探测服务发起真实请求；本机虚拟机 IP HTTPS 验证不能证明用户生产服务器的公网 IP 或入站可达性。

没有访问或修改生产面板。Docker / Octane 完整安装、MySQL / PostgreSQL 全流程、生产备份恢复、旧 Go UUID / Observer、客户端代理流量和已运行节点迁移不属于本次新增检查。防火墙规则保存也不能代替云安全组和节点到面板的实际连通验证。
